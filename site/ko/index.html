주요 기능

할 일은 둘, 도구는 하나.

모든 앱에는 좋은 스토어 페이지와 그 페이지를 돌봐 줄 누군가가 필요해요. Vitrin은 둘 다 해 줘요.

스토어 페이지 만들기

Claude가 코드와 경쟁 앱을 읽고, 스토어 페이지에 필요한 모든 것을 쓰고 디자인해요.

  • 이름, 부제, 키워드, 설명, 새로운 기능
  • 모든 기기, 모든 언어의 스크린샷
  • 앱 미리보기, 크리에이티브, 앱 내 이벤트 카드
  • App Store 규칙으로 점검한 뒤 업로드

스토어 운영하기

팀의 모든 앱을 네이티브 창 하나에 담았어요. App Store Connect에서 하는 모든 일을 브라우저 탭 없이 할 수 있어요.

  • 버전, 빌드, TestFlight, 리뷰
  • 가격, 구입, 판매, 분석
  • 사용자, 기기, 인증서, Apple Ads
  • 버전 제출, 출시, 단계별 릴리스까지 내 책상에서

내 방식대로 사용하세요

Vitrin for Mac

네이티브 앱이에요. 두 가지 일을 터미널 없이 모두 할 수 있고, 필요한 도구도 클릭 한 번으로 설치해요.

Claude Code 플러그인

저장소에서 /vitrin을 입력하세요. Claude가 원하는 것을 묻고 모든 단계를 진행해요.

CLI와 Studio

모든 단계가 명령어예요. vitrin studio를 실행하면 같은 흐름을 로컬 웹 페이지에서 열 수 있어요.

이동 중이신가요? Remote Code를 쓰면 Vitrin이 iPhone의 네이티브 탭이 돼요. 프로젝트, 모든 단계, App Store Connect를 바로 다룰 수 있어요.

작동 방식

코드에서 스토어까지, 4단계면 끝

창의적인 작업은 Claude가, 선택은 내가 해요. 나머지는 모두 직접 읽어 볼 수 있는 검증된 명령어예요.

  1. 1

    분석

    Vitrin은 코드에서 플랫폼, 언어, 기능을 찾아내요. 모든 기능은 근거가 되는 파일을 가리키므로, 스토어 페이지에는 앱이 실제로 할 수 있는 것만 담겨요.

    Swift, Flutter, React Native, Expo를 자동으로 감지해요.

  2. 2

    조사

    국가별로 App Store를 검색하고, 기기 내 OCR로 경쟁 앱의 스크린샷을 읽고, 관련성, 인기도, 경쟁도로 키워드 점수를 매겨요.

    플랫폼과 언어는 직접 고르세요. 멋대로 넘겨짚지 않아요.

  3. 3

    제작

    Claude가 빌드나 시뮬레이터 없이 코드에서 화면을 다시 만들어요. 그런 다음 Vitrin이 스크린샷과 비디오를 렌더링하면, 내 앱의 실제 샘플을 보고 고를 수 있어요.

    실제 화면 캡처가 필요하세요? 시뮬레이터에서 앱을 빌드해 촬영할 수도 있어요.

  4. 4

    검토 및 업로드

    모든 것을 갤러리 하나에서 보고 승인하거나, 의견을 남겨 항목 하나만 거부할 수 있어요. Vitrin은 승인한 내용만 그대로 업로드하고, 스토어에 저장된 내용을 다시 읽어 확인해요.

    업로드는 asc CLI가 맡으니 Ruby를 설치할 필요가 없어요.

안전

승인 없이는 아무것도 스토어에 올라가지 않아요

Vitrin은 운영 중인 스토어 페이지를 믿고 맡길 수 있도록 만들어졌어요.

  • 처음부터 정직하게모든 헤드라인과 문구는 코드의 기능을 근거로 해야 해요. 평점은 실제 App Store에서, 사용자 후기는 내 앱의 리뷰에서만 가져와요.
  • Apple보다 먼저 잡아내요명령어 하나로 텍스트, 이미지, 비디오를 App Store 규칙에 맞춰 점검하고, 무엇을 고쳐야 하는지 Claude에게 정확히 알려 줘요.
  • 파일에 묶인 승인승인할 때 모든 파일의 해시를 기록해요. 이후에 무엇이든 바뀌면, Claude가 바꾼 것이라도 다시 승인받아야 해요.
  • 부분 업로드는 부분만드라이런 계획이 먼저예요. 선택하지 않은 것은 삭제되거나 덮어쓰이지 않고, 모든 업로드는 다시 읽어 확인해요.

이어서 실행 가능

바뀌지 않은 단계는 건너뛰어요. 키가 없어도 작업은 멈추지 않고, 업로드만 키를 기다려요.

깔끔한 저장소

모든 것이 metadata/ 폴더 하나에 담기고 git에서는 제외돼요. 키는 .env에 보관되고 모든 로그에서 가려져요.

맞춤형 제품 페이지

맞춤형 제품 페이지, 앱 내 이벤트, 앱 에셋 라이브러리도 스토어 페이지와 함께 업로드할 수 있어요.

스토어 규칙 내장

글자 수 제한, 키워드 규칙, App Review 정책을 언어별로 점검한 뒤에 결과를 보여 드려요.

자주 묻는 질문

궁금한 점, 답해 드려요

Flutter나 React Native 앱에서도 되나요?

네. Swift와 SwiftUI를 우선으로 지원하고, Flutter, React Native, Expo 프로젝트도 자동으로 감지해요. 화면은 빌드 없이 코드에서 다시 만들거나, 원한다면 각자의 도구로 빌드해 시뮬레이터에서 캡처할 수 있어요. Vitrin은 App Store용이므로 Apple 플랫폼용 앱만 다뤄요.

OpenAI나 Anthropic API 키가 필요한가요?

아니요. 창의적인 작업은 내 Claude Code 세션 안에서 이뤄지고, CLI는 AI를 호출하지 않아요. Claude 없이 브리프를 보고 직접 작업할 수도 있어요.

iPhone에서 사용할 수 있나요?

네. Mac에 Remote Code 1.6이 있으면 Vitrin이 iPhone의 탭이 돼요. 프로젝트 폴더를 추가하고, 모든 단계를 실행하고, App Store Connect를 네이티브 화면에서 관리할 수 있으며, Vitrin for Mac을 열어 두지 않아도 돼요. 프로젝트는 iPhone과 Mac 사이에서 동기화돼요.

Mac 앱을 쓰려면 터미널이 필요한가요?

아니요. 환영 투어가 Mac을 점검하고 Node.js, Vitrin CLI, Claude Code, asc CLI, ffmpeg를 클릭 한 번으로 설치해요. Homebrew가 있으면 사용하고, 없어도 괜찮아요.

키를 직접 만들지 않고 App Store Connect를 연결할 수 있나요?

네. Apple 계정으로 로그인하면 Vitrin이 관리자 API 키를 한 번에 만들어요. 키를 직접 추가하거나 asc CLI에 이미 있는 로그인을 사용할 수도 있어요. 프로젝트는 연결 없이도 작동해요.

App Store Connect에 새 앱을 만들 수 있나요?

Apple 계정으로 로그인하면 Vitrin for Mac에서 만들 수 있어요. Apple은 API 키로 앱을 만드는 것을 허용하지 않기 때문에, CLI와 플러그인은 앱이 없으면 멈추고 알려 줘요.

묻지 않고 업로드하는 일이 있나요?

아니요. 모든 이미지, 비디오, 텍스트를 먼저 보여 드려요. 업로드는 드라이런 계획으로 시작하고, 사용자의 승인이 있어야 하며, 승인한 내용과 다르면 거부돼요. 심사 제출에는 별도의 확인이 필요해요. 플러그인에서는 가격, 출시, 연령 등급과 개인정보 설문을 직접 처리해요.

정확히 무엇이 업로드되나요?

승인 후 선택한 플랫폼과 콘텐츠만 업로드돼요. 선택한 스크린샷 세트는 디스플레이 유형별로 교체되고 나머지는 그대로 유지돼요. Vitrin은 빌드를 업로드하지 않아요.

앱을 빌드해야 하나요?

아니요. 기본적으로 Claude가 소스 코드에서 화면을 HTML로 다시 만들기 때문에 빌드도, 시뮬레이터도, 데모 모드도 필요 없어요. 실제 캡처를 원한다면 앱을 빌드해 전용 시뮬레이터에서 각 화면을 열 수도 있어요.

생성된 파일은 어떻게 되나요?

프로젝트의 metadata/ 폴더에 남고, 관리되는 .gitignore 블록이 git에서 제외해 줘요. 업로드 확인이 끝나면 Vitrin이 조사 데이터를 삭제할지 물어봐요. 그 외에는 아무것도 삭제되지 않아요.

라이선스는 어떻게 되나요?

Vitrin은 MIT 라이선스예요. OFL 글꼴과 Lucide 아이콘을 포함하고, 스타일 프리셋은 ParthJadhav/app-store-screenshots(MIT)를 바탕으로 했어요. 앱 미리보기는 Remotion으로 렌더링하는데, 개인과 직원 3명 이하의 회사는 무료로 쓸 수 있어요. 더 큰 팀은 Remotion 회사 라이선스가 필요해요.

Apple 제품인가요?

아니요. Vitrin은 독립적인 오픈 소스 프로젝트이며, Apple Inc.와 제휴 관계가 없고 Apple Inc.의 보증이나 후원을 받지 않아요.
